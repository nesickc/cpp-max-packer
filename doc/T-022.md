# T-022: pinned Benchy, benchmark command and regression qualification

Status: planned; no acquired fixture or passing evidence presumed.
Proposed branch: `feature/QA-01-benchy-qualification` (not created).
Prerequisites: [T-015](T-015.md), [T-016](T-016.md), [T-020](T-020.md) and [T-021](T-021.md), merged into `main`.
Start the branch only after those prerequisites and this planning change merge.
Fixture acquisition may occur as early as T-009 when needed; final qualification
and [MILESTONES.md](MILESTONES.md) delivery order remain this ticket's responsibility.

## Scope and boundary

Implement the required §8.1 standalone `benchmark` suite/output surface and
assemble repeatable full-controller CPU/Radeon comparisons, synthetic correctness
and host-specific regression baselines. Pin official Benchy before any positive
claim; supplied assets complement it. This establishes M4/M6 quality evidence,
not installer qualification (T-023), an invented Benchy count or a global optimum.

## Governing requirements

QA-01/QA-02, SOL-01/SOL-02/SOL-04/SOL-07/SOL-08 and DATA-01/DATA-03;
AT-05–AT-12 and AT-17, relevant AT-02/AT-14/AT-16 regressions. Canonical
spec §§8.1/8.3/8.5, 9.1–9.3 and 10.1 govern. ADR 0011 and shared evidence apply.

## Observable acceptance

1. **T022-A1:** Pin the actual official 3DBenchy acquisition: URL/date, byte hash,
   license/provenance, units, bounds/triangles, accepted hash and validity/repair
   report. Keep original/repaired inputs distinct; never fetch a moving latest file
   during runs. Synthetic fixtures retain checked-in generation parameters.
2. **T022-A2:** `benchy_small` uses 128 cubed mm, 1 mm gaps/pitch, Cube 24,
   120 s; `benchy_standard` uses 165x165x320 mm, 1 mm gaps/pitch, Free 256,
   600 s. Preserve computed validated AABB baselines and initial spectral incumbents.
   Only `benchy_detail` (0.5 mm/Free 2,048/3,600 s) is the optional long profile;
   unsupported detail hardware is recorded, never silently coarsened.
3. **T022-A3:** Standard seeds are exactly 1/2/3/4/5. Report best/median/worst
   counts, counts plus poses, improvement times, preprocessing/search/validation/
   export and cold total time, peak RAM/VRAM, transitions, actual pitch/catalog,
   threads/cache state, build/dependency/OS/device/driver and every failed seed.
4. **T022-A4:** Compare AABB baseline, greedy spectral with improvement disabled
   and full search under identical geometry/gaps/pitch/permissions/total budgets.
   Also compare fixed work; independently timed runs need not share greedy poses,
   while the full run must preserve its own initial greedy incumbent.
5. **T022-A5:** Independently invoke the standalone validator on every result and
   actual STL assembly. Fail on invalid/indeterminate published geometry or export;
   retain failures. Exercise cube 64, tilted bar, exact AT-11 rearrangement,
   concave/cavity/clearance/thin-feature and million-triangle/LOD invariants.
6. **T022-A6:** Regress `ulamok_box_36`, both full Pryaniks and explicitly accepted
   reconstructed Pryanik, preserving hashes/repair resolution and supported-profile
   counts/poses. Original invalid simplified geometry remains a rejection case.
7. **T022-A7:** Commit CPU and actual Radeon reference-host runtime/memory
   baselines before M6. Investigate median-count loss >5% or runtime increase >20%;
   an accepted baseline change needs explicit evidence. Correctness always blocks
   release. Measure FFT and whole-workflow GPU ratios separately.
8. **T022-A8:** Benchmark help/schema/capabilities, invalid suite/settings, structured
   failures and count-and-placement outputs are reproducible. Fixed-work repeats
   at the same build/thread configuration match; watchdog aborts remain failures.

## Tests, evidence and review

Use spec-linked red/green runner/output cases and real release-candidate suites.
Prespecify numerical targets/sampling; shared bounded comparisons use one warmup
and five timed samples unless a justified alternative was recorded beforehand.
Canonical standard five-seed coverage remains required. Keep complete raw artifacts
under `.local/t022/` and commit compact manifests/settings/evidence with reproduction commands.
Routine independent benchmark/contract review applies; unresolved numerical or
physical-validity concerns require focused critical review, not a rebaseline.

## Open decisions and compatibility

Freeze suite schema, baseline profile/version, qualification hosts and fixture
distribution provenance before runs. Choose actual fixture hashes only after
acquisition. Preserve unsupported-schema errors and existing result compatibility;
fixture/runner success alone cannot establish product or Windows release gates.
