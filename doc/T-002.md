Branch: `feature/AT-13-protocol-contracts`. Base: merged T-001/PR #2 at `2568c38a7814aef71c5d2c4c4d1f614fff289772`. Status: implemented, locally verified and reviewed by Astra Extra High. [Feature CI](https://github.com/nesickc/cpp-max-packer/actions?query=branch%3Afeature%2FAT-13-protocol-contracts) records hosted qualification; user review and merge remain required.

Requirements: DATA-01, spec §§8.1 and 8.3; contract groundwork for AT-13/AT-14. This task supplies versioned schemas, shared native decoding/semantic checks, generated TypeScript, process-local asset IDs, and a working capabilities CLI/stdio handshake. Import, solver jobs, checkpoint recovery and product acceptance remain later work.

The schemas are the authoritative structural contracts. A pinned Draft-07 validator consumes those schemas in C++; an independent validator checks the shared fixture corpus. TypeScript is generated from the same files and checked for stale output and type errors. The service uses bounded UTF-8 NDJSON records, explicit structured errors and session-local request deduplication. Capabilities distinguish implemented methods from later operations.

Acceptance requires observed failing behavioral tests, passing native and independent schema tests, process-level CLI/service checks, bounded protocol timings, configured code review, and hosted Windows evidence. No fixture or successful schema check establishes authoritative geometry validity.

## Contract and service boundaries

- Draft-07 schemas define requested/resolved settings, inspected/accepted assets,
  `best_found` results, protocol envelopes, and benchmark summaries. The native
  resolver and TypeScript generator use a closed six-document catalog.
- Native checks cover source units and frames, quaternion normalization and
  permissions, pose matrices, content-reference relationships, run segments and
  transitions, volume availability, and report consistency. They do not open
  referenced files or validate geometry.
- The service counts raw UTF-8 bytes, flushes complete responses, rejects malformed
  framing, and retains bounded replay records. It handles unsupported methods and
  resource failures explicitly. Its registry supplies non-reused session handles
  for caller-provided immutable snapshots.
- Build metadata records a dirty working tree explicitly. A configured capability
  surface is distinct from implemented import, packing, projects, or exports.

The serialization decisions and compatibility boundary are in
[ADR 0004](../spec/decisions/0004-versioned-contracts.md). Fixtures and regeneration
commands are described in [the contract test README](../tests/contracts/README.md).

## Performance scope

The bounded service workload validates and replies to 1,000 repeated capability
requests per sample, including exact replay checks. One warmup precedes five
samples. Reports include build and environment metadata; timings include service
startup and transport overhead. Existing direct-correlation and analytic-fixture
reference timings remain separate. These measurements establish no packing speed,
GPU acceleration, stop-latency, or capacity claim.

On this local Release build, the service sample median was 22.143 ms (range
21.927–22.545 ms). The reference correlation median was 0.247 ms and analytic
fixture construction median was 0.7981 ms. Reports retain host, compiler/build and
workload metadata; these informational measurements are not portable thresholds.
