## Problem and evidence limits

Start currently invokes separate prepare and solve processes. Both reconstruct
the accepted source; prepare also recreates the display LOD. The search clock
starts after asset/context/catalog loading and ends before result publication.
The historical practical 10 s setting produced 31.1 s total / 11.13 s search;
it is neither a current Release baseline nor a measurement of the largest phase.
Stop is acknowledged promptly in existing tests, but preparation consumes its
remaining native call before the marker is checked. Completion is a separate gate.

## Bounded outcome

Reuse immutable accepted-asset preparation and unchanged preview data with bounded
ownership, and enforce one monotonic deadline beginning at Start registration.
Charge job-specific loading/preparation, FFT planning, search and validation to it;
report previously completed import diagnostics separately. Stop beginning new
search work at the deadline, perform bounded safe cleanup and report any overrun.
Expose truthful total/phase elapsed time and termination cause through the desktop.
Existing results retain the settings and timing semantics that produced them.

Cancellation starts before heavy job preparation and reaches bounded safe points
in every ordinary qualified phase. Only valid immutable incumbents may replace
the displayed/saved result. A deadline before a nonempty incumbent is available
must state that fact; neither a trial nor an unvalidated empty result is published.
Only the serial geometry/work reductions needed for the carried T-009 gates are
included; no general geometry tuning, new search policy, parallel worker system,
GPU, runtime checkpoint/Continue or live viewer stream. Basic phase/error feedback
is included. Audit existing complexity before adding further mechanisms.

## Decisions and compatibility to freeze

Choose one native ownership/adapter design with an architect: a combined run or
retained engine context, its lifetime, memory cap and eviction/invalidation keys.
Rust and JavaScript never authorize accepted solids from cached report assertions.
Bind reuse to source/accepted hashes, role, units/frame, repair recipe/version and
native implementation version; derived fields also bind constraints/pitch/catalog.
Pin immutable input bytes/handles or detect mutation before reuse. Untrusted
project restore must still verify/replay assets and revalidate placements; export
keeps its independent geometry and quantized-coordinate checks.

Freeze deadline/Stop transport, phase boundaries, cleanup maximum per qualified
profile, race ownership and failure semantics. Use a monotonic clock for budgets;
wall timestamps remain provenance. Specify conversion across process boundaries.
Update versioned settings/results/desktop timing contracts before semantic changes.
Define legacy search-only budget loading/display explicitly; old saved runs must
not silently acquire a new total-budget interpretation. Preserve single-thread
and T-010 configurations. Document the first-run/preparation-stop result behavior.

## Observable acceptance

- **T011-A1 — one budget.** Inject or reproduce expensive preparation, planning
  and validation through production paths. They consume the same Start-origin
  budget; a 10 s setting does not restart a 10 s allowance at each subprocess.
  At deadline no new search work begins. Record cleanup and positive overrun
  separately, including a run exhausted before a nonempty incumbent exists.
- **T011-A2 — real reuse.** Repeated Start on unchanged geometry does not recreate
  its LOD or replay equivalent accepted preparation unnecessarily. Exercise New,
  replacement import, units/frame/repair changes, constraints/pitch/catalog and
  engine-version changes; reuse is either valid or invalidated deterministically.
  Cache eviction changes performance only, never validity or physical dimensions.
- **T011-A3 — tamper resistance.** Modify source, accepted PLY, repair evidence,
  settings/catalog or restored poses independently. Native paths reject the change
  or rebuild from verified authority; no stale authorization becomes active. Moved
  archives still restore valid results and failed Open preserves complete state.
- **T011-A4 — Stop phases.** Exercise loading, preparation, fields, FFT, candidate
  validation and terminal publication with real native work. Receipt is ≤250 ms;
  ordinary qualified safe-stop completion is ≤5 s. UI remains interactive and
  stopping persists until completion. Retain the valid incumbent or previous
  complete result according to the frozen first-run/preparation-stop contract.
- **T011-A5 — lifecycle races.** Cover repeated/stale Stop, completion race,
  failed marker/transport, child failure, shutdown and late worker completion.
  No unfinished trial replaces an incumbent; workers/children are reclaimed.
  A terminated child is not a passing cooperative-Stop observation.
- **T011-A6 — measured startup.** Before optimization retain one warmup and five
  serial Release cold/warm samples for T-009's practical profiles. Freeze numerical targets
  for repeated preparation and fixed-work Start time, plus memory/cleanup bounds.
  Meet the targets while preserving fixed-work counts/poses and declared caps.
  Report intentional search time separately from overhead and cold import/export.
- **T011-A7 — compatibility journey.** Load a legacy project/result and round-trip
  new timing/settings through Save/move/Open. Verify pending/result association,
  native pose validity and independent JSON/STL export. Thread policy remains
  recorded; changing packing pitch cannot change accepted repaired geometry.
