# T-019: explicit Vulkan/VkFFT compute and CPU/GPU oracles

Status: planned; no implementation or passing evidence claimed.
Proposed branch: `feature/SOL-02-vulkan-compute` (not created).
Prerequisites: [T-010](T-010.md) and [T-016](T-016.md), merged into `main`.
Start the branch only after those prerequisites and this planning change merge.
CPU improvement precedes GPU delivery; [MILESTONES.md](MILESTONES.md) governs.

## Scope and boundary

Implement the selected Vulkan/VkFFT compute path, bounded fields/reductions,
plans and caches through the compute boundary. Qualify explicit Vulkan first
against CPU and independent integer oracles. Geometry remains CPU double
precision and authoritative. Auto selection/device-loss fallback is T-020;
this ticket cannot claim Auto or complete M5. No CUDA/HIP/ROCm dependency,
new search policy or speculative library/version pin is authorized by this plan.

## Governing requirements

SYS-02/SYS-03, SOL-02/SOL-05/SOL-07/SOL-08, GEO-04/GEO-06 and QA-02; AT-02/GPU AT-12,
AT-05/AT-16 subsets. Canonical spec §§4.2–4.3, 6.3/6.6, 9.2–9.3 and 10.1
govern. [ADR 0011](../spec/decisions/0011-cpu-first-follow-up.md) preserves CPU priority.

## Observable acceptance

1. **T019-A1:** Detect required device features and run a startup FFT self-test;
   vendor name alone is insufficient. Support single precision without device
   FP64. Explicit CPU never initializes Vulkan; unavailable explicit Vulkan
   returns `GPU_UNAVAILABLE` with an offered CPU retry.
2. **T019-A2:** Compare every legal translation of small asymmetric fields with
   a direct integer oracle and CPU. Include non-power-of-two axes, rotations,
   nonzero kernel origins and boundaries; record reversal/conjugation, inverse
   normalization, axis order and padding at least environment+kernel-1 per axis.
3. **T019-A3:** CPU/GPU oracle values differ from integers by less than 0.25 and
   round identically. Inject bad normalization/FFT output; reject or explicitly
   recompute the unreliable pass. Numerical failure cannot prove impossibility
   or authorize a placement; discrete and original-solid checks remain required.
4. **T019-A4:** Preflight all live padded buffers, plans/shaders, staging, fields,
   geometry/validation/viewer reserves and CPU worker scratch. Enforce 50% host
   and 60% available-device caps with downward limits and combined shared-memory
   accounting. Bound LRU spectra/plans and batches; manual pitch never changes silently.
5. **T019-A5:** On an actual recorded Windows Radeon, run detection, self-tests,
   oracle suite and pinned `benchy_small`, then force CPU and repeat. Every saved
   layout passes independent native validation and retains its AABB baseline.
   Acquire/pin the official fixture before use; early acquisition does not claim T-022.
6. **T019-A6:** Test allocation/resource failures and safe cancellation without
   corrupting the incumbent or reusing unfinished buffers. Preserve nested error
   codes and device/build/driver information; runtime Auto recovery awaits T-020.
7. **T019-A7:** Report measured GPU/CPU ratios for FFT work and complete workflows
   separately, with counts/poses, actual work, thread count and cold/warm state.
   CPU/GPU heuristic poses need not be identical; both satisfy the same validity rule.

## Tests, evidence and review

Use practical red/green backend/oracle cases before tuning and real Radeon runs,
not emulated device or CPU-only success. Freeze any numerical speed target and
the measurement profile before optimization; use shared warmup/sample rules.
Keep raw logs/settings/poses/memory and hardware metadata in `.local/t019/`.
An architect freezes backend/resource ownership; numerical/Vulkan uncertainty
and device synchronization require focused critical review.

## Open decisions and compatibility

Settle dynamic-loader, shader/planning distribution, compute ABI, cache keys and
device-budget queries before implementation. Record actual selected stack
revisions only after the dependency/build decision, updating notices/contracts
as needed. Keep Auto explicitly unqualified until T-020; no CPU validity shortcut.
