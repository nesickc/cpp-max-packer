## Observable acceptance and red/green order

1. **CPU correlation / AT-12.** Add runtime tests of production correlation
   against existing `direct_linear_cross_correlation` before implementation.
   Compare every full-linear translation, not just selected peaks, for binary
   asymmetric 3D fields, shapes such as 2×3×5, nonzero positive/negative kernel
   origins, nonzero environment first, all axis rotations and boundary-only
   overlap. Require absolute error `<0.25` and identical integer rounding.
   Explicit impulses catch reversal, bad conjugation, normalization and circular
   aliasing. Keep the existing oracle independent.
2. **Fault/preflight / AT-12.** At the real numerical-check seam inject incorrect
   inverse scaling, integral output corruption and NaN. Assert an unusable failure
   result, never a collision-free field or negative feasibility conclusion.
   Check shape/product/index overflow and resource refusal before allocation,
   checked plan/scratch reserve, probe work exhaustion and zero-filled fields.
   Compare proximity to an independent tiny direct sum and nearest-blocked-cell
   brute-force distance field; it must be normalized across kernel populations.
3. **Spectral placement / SOL-02, SOL-03.** Keep baseline exact64/clearance64/empty
   regressions. Use a small asymmetric accepted object with fixed, all 24 cube,
   and non-cardinal custom catalogs; verify unchanged physical coordinates and
   allowed rotations with the real validator. A fixture must actually exercise
   spectral correlation and an accepted spectral proposal; baseline-only success
   is insufficient. Exercise page 33+ after rejecting the first page, deterministic
   orientation/Z/Y/X ties, off-grid baseline mask construction and conservative
   voxel contact bypass. Verify the central best never worsens on invalid,
   indeterminate, unreliable, stopped or exhausted trials.
4. **Transforms / DATA-03, AT-14 subset.** Use analytic non-origin source vertices
   with explicit non-mm scale and a nontrivial quaternion. Independently calculate
   `R*(s*p-anchor)+t`, compare JSON source/local matrices and re-read STL vertices.
   Include cardinal rotations preserving exact cube tilings, container origin
   translation with unchanged axes, count/pose mismatch and tampered metadata.
   Schema/semantic success alone cannot establish geometric validity.
5. **STL round-trip / AT-10.** Re-read all 64 cube copies under recorded triangle
   ranges; prove containment, pair gaps and equality to expected vertices. Treat
   touching copies separately, with no boolean union or assembly manifold demand.
   Too-large object emits valid empty `best_found` JSON and zero-triangle STL.
   Output count, utilization and dimensions are independently checked.
6. **Quantization refusal / DATA-03.** Use an analytically valid positive gap below
   float32 resolution at a chosen representable large translation, so rounded
   coordinates collapse or violate the requested gap. The reread check must fail
   STL while preserving valid JSON and original poses. Also reject a collapsed
   face, nonfinite float, corrupted/truncated range and read/write failure. Include
   a cavity/enclosure case so an AABB-only export checker cannot pass the suite.
   Per-copy import must not clean up collapsed geometry into a different solid.
7. **Reachable CLI.** Existing `inspect` outputs feed the ADR's synchronous
   `solve --settings ... --object-report ... --result ... [--stl ...]` command.
   Test a real process, output JSON against the shared contract validator, source
   and accepted hashes, relocated portable artifacts, and reread full-resolution
   STL/companion. Test repaired accepted input or explicit reconstruction failure;
   never silently substitute the unrepaired source. Unsupported advanced modes
   fail clearly. CLI/service import/capability regressions remain green.
8. **Practical retained evidence.** Use accepted `rc/` solids with their pinned
   manifest hashes and millimeter/interior-volume conventions. Begin with one
   tractable accepted item/container pilot, manual pitch, fixed identity, one
   thread and small fixed work. Retain source/accepted identities, resolved
   settings, baseline and final counts **and poses**, counters, termination,
   timings, JSON/STL and independent reread verdicts. Require final count at least
   baseline for the same baseline slice. Repeat twice on the same build/config;
   compare counts and transforms, excluding elapsed timestamps. Expand practical
   coverage only within measured tractability; watchdog aborts are incomplete.

## Verified CPU correlation component

The production CPU component uses pinned pocketfft with full complex double
transforms. All 15 focused cases pass in Debug and Release on the measured
`local-windows-2026-20260921` profile. The matrix checks every world-labelled
translation against the independent oracle, an asymmetric 2×3×5 kernel under
all 24 proper cube rotations, general-radix length 13 and Bluestein length 127 on
each axis, proximity sums, zero fields, numerical fault rejection, signed-index
overflow and memory/work limits. Configured Astra Extra High review found no
production correctness defect; its two acceptance gaps were filled and closed.

Complete local logs: `compute-reliability-red.log` (5/11 failures),
`compute-translation-last-red.log` (1/12 failure), and
`compute-qualification-debug.log` / `compute-qualification-release.log`
(15/15 each, terminal exit 0), all under `.local/t007/`. The later rotation and
FFT-path cases were characterization checks and already passed; they are not
claimed as additional red evidence. `orientation-red.log` is a configure failure
from a transient missing source during a concurrent edit, not a runtime red.

The source-audited workspace reserve covers both complex grids, output, probes
and scalar pocketfft plan/scratch storage; cache, threading and vector paths are
disabled. It excludes allocator metadata and is not process RSS. A dependency or
execution-mode change requires re-audit. Solver use, artifact round trips and
full T-007 acceptance remain pending.
