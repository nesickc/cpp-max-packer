# T-003: STL import and accepted geometry

Branch: `feature/AT-03-stl-import`. Base: merged T-002/PR #3 at
`6af862e3c978b16447ba13758d45bdf044b767e7`. Status: architecture and test-first work
in progress.

Requirements: GEO-01–GEO-03, spec §§5.1–5.2 and the `inspect` command in §8.1.
AT-03/AT-04 supply the import and repair cases. T-004 retains independent
placement/containment/clearance validation; T-005 retains display LODs and fields.

This ticket introduces a native import boundary that preserves source bytes,
requires explicit units, records object/container frames, diagnoses the full mesh,
and controls creation of immutable accepted geometry. Safe exact cleanup is
reported. Tolerance welding is an explicit bounded proposal whose acceptance is
separate from inspection. Invalid or indeterminate geometry cannot become an
accepted solid.

## Observable cases

- Equivalent ASCII/binary cubes, misleading binary `solid` headers, multiple
  components, negative coordinates and Unicode paths.
- Millimeters, the 25.4 mm inch cube, positive custom scales, and independent
  source-to-local reconstruction for objects and containers.
- Structured failures for malformed/truncated data, nonfinite coordinates and
  resource limits; source bytes and hashes remain unchanged.
- Reported exact cleanup, reversed winding, open/non-manifold meshes,
  self-intersection, touching/overlapping shells, preserved nested cavities, and
  a small seam requiring explicitly accepted welding.
- Practical diagnostics for all ten pinned `rc/` assets, with acceptance outcomes
  established by the importer rather than inferred from closed-edge counts.
- A bounded import timing workload with fixed input, correctness checks, build
  metadata and a watchdog. It establishes no packing-performance claim.

## Performance workload

Run all ten manifest-pinned files through the public inspection command once,
checking source hashes, byte/triangle counts, original bounds, frame mapping and
the actual acceptance verdict. The six analytic box containers require valid
acceptance and their independently computed box volumes. Item verdicts are pinned
only after diagnostic review; a defect is retained as a regression case.

Measure three Release inspections of the largest source (`pryanik_2.STL`) after
one warmup. Retain each sample, median and nearest-rank p95, source/executable
hashes, build metadata, machine identity and work counters. Use a per-process
watchdog and an overall bounded run; timing is initially informational, with no
cross-machine regression percentage or invented solver target. Every timed sample
must reproduce the reviewed diagnostic outcome and complete checks. A timeout or
changed outcome fails the workload rather than becoming a timing sample.

Raw red/green, kernel-characterization and timing evidence stays in `.local/t003/`.
Shared interfaces and serialization decisions will be recorded before behavioral
implementation. Routine changes should avoid expanding generated JSON fixtures;
small native fixture builders provide analytic expectations.

## Development evidence (qualification pending)

`.local/t003/import-phase1-green.log`. Its original red fixture accidentally
contained only seven bytes; the attempted correction ran no tests. Neither is
claimed as a valid parser TDD red. A subsequent isolated build of the actual

the leading-plus ASCII parsing defect: 6 cases, 37 assertions, one failed
assertion (`.local/t003/import-phase2-red.log`). That regression precedes its fix.
Kernel and CLI behavior have separate failing tests. Full accepted-solid, repair,
integration and performance gates remain pending.
