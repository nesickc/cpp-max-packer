# T-016: presets, automatic resolution and resource controls

Status: planned; no implementation or passing evidence claimed.
Proposed branch: `feature/SOL-05-resource-presets` (not created).
Prerequisites: [T-010](T-010.md), [T-013](T-013.md) and [T-014](T-014.md), merged into `main`.
Start the branch only after those prerequisites and this planning change merge.
Delivery priority and shared evidence follow [MILESTONES.md](MILESTONES.md).

## Scope and boundary

Resolve usable Fast/Balanced/Thorough settings, automatic pitch and advanced
thread/memory controls before allocation. Display actual resolved settings and
specific resource diagnostics for box/STL jobs. Account for the complete padded
working set, bounded caches and worker scratch. CPU qualification is this ticket;
Vulkan accounting/operation is reverified in T-019/T-020. Auto GPU selection is
not qualified here. Live viewing and additional count operators remain separate.

## Governing requirements

SOL-03/SOL-05/SOL-08, UI-01/UI-03 and GEO-02/GEO-04; AT-05/AT-15/AT-16
subsets. Canonical spec §§6.4–6.6, 7.1–7.2 and 8.3 govern. This contributes
to M3 resource controls; [ADR 0011](../spec/decisions/0011-cpu-first-follow-up.md) applies.

## Observable acceptance

1. **T016-A1:** Resolve Fast to 60 s/Cube 24/longest axis divided by 64;
   Balanced (default) to 600 s/Free 256/divided by 96; Thorough to
   3,600 s/Free 2,048/divided by 160. Explicit orientation restrictions override
   preset choices; defaults visibly use 1 mm pair and wall gaps, editable to zero.
2. **T016-A2:** Store concrete resolved settings, catalog/hash, backend and thread
   count with each job. Show pending edits separately; later preset changes cannot
   rewrite old results. A first box run requires import, dimensions and Start.
3. **T016-A3:** Preflight authoritative meshes/BVHs, fields/halos, padded FFT
   real/complex buffers, plans, staging, spectra/cache batches, validation, viewer
   reserve and every worker/nested-library scratch allocation. Check against
   measured live peaks, including growth and eviction; unpadded mask size is insufficient.
4. **T016-A4:** Apply the §6.6 50%-available-RAM host cap and downward user
   limits. Define the 60%-device-budget and shared-memory accounting contract for
   GPU consumers without claiming device qualification before T-019/T-020.
5. **T016-A5:** Automatic resolution increases pitch before Start until supported
   and displays it. Manual pitch fails specifically with a suggested supported
   value; it never silently changes. Keep physical assets/container/gaps immutable.
   If no permitted pitch fits, reject specifically; coarsening cannot solve mesh
   or validation storage already exceeding the cap and cannot continue unboundedly.
6. **T016-A6:** Test near-cap and rejected million-triangle/thin-feature workloads,
   and the reported Ulamok 1 mm grid. Early resource rejection and a supported
   independently validated at-least-36-copy run are separate required observations.
7. **T016-A7:** Allocation faults, cache exhaustion and invalid settings leave the
   UI interactive and preserve the incumbent. Specific nested codes/phase remain
   visible; unsupported backends are labeled unavailable rather than successful.

## Tests, evidence and review

Use red/green resolver and live-allocation cases, independent padding arithmetic,
real native desktop journeys and peak-memory evidence in `.local/t016/`.
Apply shared sampling rules to measured comparisons; retain settings/counts/poses,
actual commands, failed cases and host/thread provenance. Freeze shared resource
contracts with an architect; accounting/concurrency uncertainty gets critical review.

## Open decisions and compatibility

Settle resource-query semantics, cache reserves, thread admission and preflight
DTO/versioning before edits. Assess legacy manual CPU settings and project replay;
store resolved values without retroactively resolving old jobs. New GPU budgets
need actual device evidence later, and no dependency/version is chosen here.
