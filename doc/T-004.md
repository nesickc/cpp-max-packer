## Delivered behavior

The native `pack_geometry` API validates rigid layouts against retained accepted
solids, separate pair/wall clearances, and analytic-box or accepted STL containers.
Only a completed `valid` result mints an immutable `ValidatedSolution` bound to
the original context, poses and report. Invalid or indeterminate results cannot
authorize a layout. Factories privately copy caller buffers, and opaque handle
types disable value copy/move operations to preserve that guarantee.

Practical tests cover separation, contact, tiny positive overlap, coincidence,
enclosure, disjoint components and legitimate cavities; all six fractional box
walls; concave U-volume containment and a bridge across its empty space; and an
object enclosing an excluded container cavity. Independent distance cases include
vertex/face and edge/edge interiors, exact thresholds and separate pair/wall gaps.
Large translations, tiny features, near-unit quaternions, angular permissions,
resource exhaustion and an undersized-proxy false pass have regression cases.

The kernel retains local coordinates and rigid pose expressions. Conservative
interval certificates, bounded exact cardinal predicates, complete cuboid
certificates and shell material classification establish physical validity.
Classification epsilon never discounts clearance or permits positive overlap.
Arithmetic capacity, nondefault floating environments and work/storage limits
fail closed. General noncardinal close/contacted arrangements can remain
`indeterminate`; exact cardinal arithmetic has a checked 32,768-bit capacity.
Tracked working storage is reported separately from process RSS.

## Bounded performance

The [qualification plan](../benchmarks/VALIDATION_PLAN.md) fixes workloads and
evidence rules. Source import/setup is separate from complete validation timing.
On the local `local-windows-2026` Release profile, setup took 9439 ms. The slowest
workload by median was the separated Pryanik 2 pair in `10_kg_np.stl`: median
515.05 ms, nearest-rank p95 528.79 ms. The 64 separated cubes took median 2.25 ms,
p95 2.27 ms, with 2016 AABB pair checks and 62,776 charged kernel work units.
Three samples provide a bounded baseline, not a tail-latency guarantee.

Reference and service replay timings also passed. Timing results are
informational, with no cross-machine threshold, solver throughput or capacity
claim. The practical layouts establish that those supplied poses are valid.

Solver lifecycle, serialized-layout validation, LODs, exports and desktop
integration remain separate tickets. This native boundary does not complete
full AT-08 search behavior, M1 or the product release gates. Dependent work waits
for the user's merge.
