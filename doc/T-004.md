# T-004: independent solid validator

Branch: `feature/AT-06-solid-validator`. Base: merged T-003/PR #4 at
`08d094ba31ba28249fdf2ec8490c29db2ea63265`. Status: contracts and test-first
acceptance design in progress.

Requirements: GEO-05/GEO-06, spec §§5.2–5.3, AT-06/AT-07/AT-09, and the
orientation-permission portion of AT-08. This ticket supplies a native validator
over immutable accepted solids, independent of search and display geometry.
Only a completed `valid` result can yield a publishable validated layout.

## Observable acceptance

- Pairs: separated solids, exact zero-clearance contact, positive overlap,
  coincidence, full enclosure, disjoint components and legitimate cavities.
- Containers: all six analytic box walls, fractional dimensions, valid concave
  STL poses, a bridge across a U-shaped volume, and an object enclosing an
  excluded container cavity without crossing its surface.
- Clearances: independent pair and wall values; Euclidean gaps below, at and
  above the requested threshold. Classification tolerance never discounts the
  gap or permits positive overlap. Cover near-coplanar/tiny features and large
  translations, with explicit uncertainty when a result cannot be resolved.
- Input and publication: finite rigid XYZW poses, permitted orientations,
  authoritative asset/constraint binding, duplicate copy IDs, bounded work,
  and rejection of invalid or indeterminate layouts. An undersized proxy cannot
  replace authoritative geometry.
- Practical fixtures: import the unchanged sources once, validate the three
  accepted items in each of the six accepted STL containers at independently
  known centered poses with 1 mm wall clearance, and validate out-of-container
  rejection poses. Derive centers from actual accepted bounds; nominal file
  dimensions and source-space centers are not placement coordinates.

[ADR 0006](../spec/decisions/0006-independent-solid-validator.md) settles the
native interface and numerical contract before physical implementation. Initial
compiled acceptance tests fail on single-solid acceptance, wall rejection and
contact/overlap classification with the explicit unimplemented kernel. Input
guards and immutable context/candidate accessors pass their focused tests.
These are implementation checkpoints, not completed geometric qualification;
evidence is retained in `.local/t004/{red-debug,red-input-debug,green-input-debug,snapshot-debug}.log`.

## Performance and delivery

Add a bounded Release validation workload through the public native API, with
fixed geometry/poses/constraints, source identity, build and host metadata, raw
timing samples, median/p95 and work counts. Include separated-pair pruning and
practical containment. Validate outcomes on every repetition; timeouts and
indeterminate results cannot become successful samples. Initial timings are
informational; no packing/search performance claim is made.

Run affected native Debug/Release, practical and staged checks, preserve T-003
import regressions, and obtain Astra Extra High review. Publish the feature
branch and a ready PR targeting `main` after hosted qualification. The user
reviews/tests/merges. Solver lifecycle, asynchronous protocol imports, exports,
LODs and desktop work remain separate tickets; this ticket alone does not
complete the full AT-08 solver scenario or M1.
