## Scope and boundary

documentation and an evidence-linked full-v1 audit. Qualify clean Windows CPU
and actual Radeon workflows without development tooling or network access.
Reconcile M0–M6 and every requirement/AT rather than treating ticket merges as
completion. Multi-object packing, manual placement editing and 3MF remain later
scope. No automatically merged release or speculative new dependency is implied.

   networking disabled and without NVIDIA tooling, Python, Node.js or a developer
   SDK. Bundle needed runtimes/shader components and offline WebView2 prerequisites;
   record installed/loaded native dependencies and package hashes/notices.
2. **T023-A2:** Desktop and standalone CLI complete import, CPU pack, view where
   applicable, Stop/Continue, portable Save/move/Open and JSON/full-resolution STL
   export. Cover box/STL containers, units/nontrivial origins, explicit repairs,
   Unicode/spaced/long paths and known valid empty results labeled `best_found`.
3. **T023-A3:** Repeat required GPU workflows on a recorded Windows Radeon/
   normal driver configuration, including Auto fallback and missing-loader CPU
   operation. Publish exact qualified OS/device/driver combinations; use the user's
   exact Radeon when available without inventing an unspecified GPU result.
4. **T023-A4:** Assemble requirement/AT/M0–M6 traceability to actual native,
   service, desktop, recovery, viewport and benchmark evidence. Every mandatory
   AT-01–AT-17 passes; only the canonical optional `benchy_detail` profile may
   retain its documented optional/unsupported status. Missing hardware is not a pass.
5. **T023-A5:** Run STL/archive/protocol parser fuzzing with declared memory/time
   caps, plus hostile-input/failure gates: malformed framing, replay,
   tampering/traversal, allocation/device loss, blocked native work and full disk.
   Record the fuzz corpus and seeds; retain every failure and its reproducer.
   Retain valid state, caps, prompt Stop and recoverable checkpoints; unrelated
   project files remain intact.
6. **T023-A6:** Every published packing/export has independent validation and
   count/pose provenance. Freeze release-host runtime/memory baselines, retain
   all five standard Benchy seeds and the 1,000-copy viewport record. Investigate
   §10.1 regressions; no suppressed failed seed or automatic weakened baseline.
7. **T023-A7:** Ship accurate install/offline/CPU/GPU/resource/repair/Continue/
   export-recovery help, generated command flags and developer build/test guidance.
   Show actual settings/backend, heuristic limits and qualified hardware. Local
   use requires no account, telemetry or model upload; document package provenance.

## Tests, evidence and review

Documentation-only edits use link/traceability validation. Packaging changes use
practical failing clean-machine/runtime cases first, then actual installer/CLI
and Radeon qualification. Keep complete logs, package hashes, machine snapshots,
counts/poses and signed-off evidence summaries under `.local/t023/`.
Routine release/package/document review applies; consequential parser, update,
recovery or validity changes trigger targeted critical review and fresh affected gates.

## Open decisions and compatibility

Settle installer/prerequisite delivery, supported runtime versions, artifact/signing
policy and version/migration behavior using verified dependencies before packaging.
Audit legacy projects/settings/repair recipes and unsupported-schema behavior.
Release claims follow actual AT/M evidence; a successful build, installer launch
or documentation audit alone cannot establish full v1.
