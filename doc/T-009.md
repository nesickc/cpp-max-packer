## Bounded outcome and decisions

Replace the quadratic proximity scan with an efficient distance/nearest-blocker
method preserving the score, physical mapping, halo convention and tie order.
Correct preflight and propagate the underlying stage/code/limits through CLI,
desktop errors and retained run evidence. Preserve the physical AABB incumbent.
Manual pitch never changes silently. An unsupported 1 mm run needs a specific
early resource response and supported-pitch suggestion, not generic `SOLVE_FAILED`.

Before code, freeze an ADR for the distance definition and numerical envelope,
work-counter meaning, live-allocation model, cache invalidation and error contract.
Keep container-mask, pose-dependent data and orientation-kernel ownership distinct.
Update contracts/generated types first where error evidence changes; old results
and explicit repaired assets must retain their existing interpretation.
Freeze exact supported profiles for Ulamok and both full Pryaniks on one host.
[ADR 0012](../spec/decisions/0012-cpu-field-scalability.md) freezes the bounded
implementation and error contract; proposed profiles still require qualification.
No multithreading, GPU, new orientation modes, general repair or live viewer stream.
If a practical blocker needs unrelated redesign, refer it for a bounded follow-up
and revise the acceptance dependency explicitly; do not silently expand this ticket.
